## Controls deliberately kept (the audits' keep-list)

Kernel journey + scope challenge · minimal-form + provenance rules ·
scope-cut / user-visible-ambiguity / strategic-dependency hard stops ·
falsifiable acceptance criteria + NFR budgets with measurements ·
production-composition rule · wire contracts + verified fakes (external
module) · migration up-down-up rehearsal (migration module) · reviewer
independence + repro-before-fix + lint-compounding on repeat findings ·
human walkthrough of the release build · doc sync + `brana-gate claims` ·
buy-before-build. All present in WORKFLOW.md; none diluted.

## Honest limitations — `d9dfa1f` snapshot (items 2 and 4 since resolved)

1. **Instruction-surface savings are measured; project-level savings are
   projected.** The −88% instruction surface and 9→1 artifact collapse are
   real numbers, but "tokens per shipped feature" can only be proven by
   running the next project under v2 and recording §Measurement metrics.
   Do not update COMPARISON.md with cost claims before that.
2. **`tools/brana-gate`'s `tasks` subcommand is orphaned** — the TOML task
   schema it checks no longer exists. `docs` and `claims` remain in use.
   The script was not rewritten (out of scope); prune `tasks` when the
   script is next touched.
3. **Long-cycle drift risk** from removing scheduled mid gates is mitigated
   by pull gates + slice screenshots, not eliminated. If a v2 project ships
   a late-discovered product problem a mid gate would have caught, that is
   the trigger to add a *conditional* mid-gate rule (with activation +
   removal conditions per the new policy) — not to restore the v1 stack.
4. **Installed-skill sync pending:** `~/.claude/skills/` still carries the
   v1 brana-1…7 skills until re-synced; stale triggers will fire the old
   names. Run the sync before the next project.

## Verdict

All 14 findings addressed; 12 verifiable now (structure/measurements), 2 are
policies whose value shows over the next cycles (F3, F14). The redesign keeps
every control that found real bugs in astryxs/chillify/begirex/s2orc while
removing the machinery both audits identified as the cost driver.

## Addendum (2026-07-31) — after the independent review

`docs/2026-07-30-brana-v2-independent-review.md` reviewed `d9dfa1f` and
correctly showed the verdict above was overstated: the architecture was
right, but the release was not executable through all install paths. All
eight of its findings were accepted and fixed:

| Ind. finding | Fix |
|---|---|
| 1. Skill-only installs omit canon + gate (high) | One distribution layout: `brana-plan` bundles `reference/WORKFLOW.md` + `scripts/brana_gate.py`; siblings resolve via `../brana-plan/`; README instructs installing all three; `tools/check-dist.sh` fails on drift or extra copies |
| 2. Self-referential ledger SHA (high) | Ledger line is `id, status, date`; commit subject carries the U-ID (`[U3]`); `git log --grep` is the SHA authority |
| 3. `sync-gate.sh` recreates 5 deleted copies (med) | Deleted; replaced by `tools/check-dist.sh` (1 source + 1 bundle, byte-identical, nothing else) |
| 4. Contrast check never ran (med) | Canon + skill now invoke `brana-gate docs PLAN.md DESIGN.md` when DESIGN.md exists; UI module names the parser-compatible table shape; behavior verified (caught a 4.48:1 row) |
| 5. Risk triggers misclassify (med) | External-system trigger = runtime third-party boundary (fake obligations conditional on a fake); auth trigger narrowed to authN/authZ, personal/sensitive data, hostile-input boundary |
| 6. Canon/router dependency contradiction (med) | Execution hard stop now says *strategic-tier* capability; routine tier explicitly never stops |
| 7. v1 residue as executable surface (med) | `tasks` subcommand removed from the gate (helpful error stub remains); `examples/dally` archived as v1 with an examples README; `examples/notes-v2` added (canon-shaped PLAN.md + ledger, passes `brana-gate docs`); plugin/marketplace descriptions rewritten for v2 |
| 8. Removal policy unauditable (low) | §Measurement footer now records active modules + rules that actually fired; absence derived |

Calibrations also applied: PLAN.md soft size budget (~2,500 words, warning
not gate).

**Explicit unadopted recommendation (recorded, not "addressed"):**
`ANALYSIS-brana-vs-superpowers.md` recommended embedding complete code in
the plan. v2 deliberately chooses prose units + implementation-time
structure, per the main audit's overprescription warning. The trade-off is
open and measurable: the first real v2 cycle should run one or two
high-risk units with code-bearing briefs against prose-only units and
compare tokens + rework in the §Measurement footer before either position
becomes canon.

Still true after the fixes: project-level token savings and behavioral
quality remain unproven until a real cycle records §Measurement metrics.
No end-to-end run has exercised plan → build → ship from a clean install;
the notes-v2 fixture covers artifact shape and gate behavior only.
