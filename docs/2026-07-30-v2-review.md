## Controls deliberately kept (the audits' keep-list)

Kernel journey + scope challenge · minimal-form + provenance rules ·
scope-cut / user-visible-ambiguity / strategic-dependency hard stops ·
falsifiable acceptance criteria + NFR budgets with measurements ·
production-composition rule · wire contracts + verified fakes (external
module) · migration up-down-up rehearsal (migration module) · reviewer
independence + repro-before-fix + lint-compounding on repeat findings ·
human walkthrough of the release build · doc sync + `brana-gate claims` ·
buy-before-build. All present in WORKFLOW.md; none diluted.

## Honest limitations

1. **Instruction-surface savings are measured; project-level savings are
   projected.** The −88% instruction surface and 9→1 artifact collapse are
   real numbers, but "tokens per shipped feature" can only be proven by
   running the next project under v2 and recording §Measurement metrics.
   Do not update COMPARISON.md with cost claims before that.
2. **`tools/brana-gate`'s `tasks` subcommand is orphaned** — the TOML task
   schema it checks no longer exists. `docs` and `claims` remain in use.
   The script was not rewritten (out of scope); prune `tasks` when the
   script is next touched.
3. **Long-cycle drift risk** from removing scheduled mid gates is mitigated
   by pull gates + slice screenshots, not eliminated. If a v2 project ships
   a late-discovered product problem a mid gate would have caught, that is
   the trigger to add a *conditional* mid-gate rule (with activation +
   removal conditions per the new policy) — not to restore the v1 stack.
4. **Installed-skill sync pending:** `~/.claude/skills/` still carries the
   v1 brana-1…7 skills until re-synced; stale triggers will fire the old
   names. Run the sync before the next project.

## Verdict

All 14 findings addressed; 12 verifiable now (structure/measurements), 2 are
policies whose value shows over the next cycles (F3, F14). The redesign keeps
every control that found real bugs in astryxs/chillify/begirex/s2orc while
removing the machinery both audits identified as the cost driver.
